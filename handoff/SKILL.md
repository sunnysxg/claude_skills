---
name: handoff
description: >
  把剩余任务和必要上下文写成交接文档，供下个 session/agent 接手。
  用户要求交接（/handoff、写交接、下个 session 继续），或 context 快满但工作未完成时使用。
---

停止写代码，把交接信息写成文档。

**位置**：`~/_sxg/handoff/{project}.md`

- `{project}` = 项目根目录名 snake_case 化（全小写，`-` → `_`）；目录不存在则创建
- **例外**：若项目根已有 `HANDOFF.md`（旧约定，个别项目的外部流程依赖它），就地更新那份，不迁移

**焦点**：调用时带了参数，就把它当作「下个 session 要聚焦什么」的描述，全文围绕它取舍——
焦点内的写细，焦点外的压成一句指针或整段省略；无参数则写全量交接。

**内容**（按下个 agent 的提问顺序）：

1. 目标：原始需求，以及现在离完成还差什么
2. 现状：已完成并验证的部分（带文件路径）；git 状态（分支、已提交/未提交）
3. 下一步：剩余工作写成可执行动作，第一步具体到能直接开工；要用的 skill 点名
4. 决策与坑：关键决策及其理由、真实约束、踩过的坑、未决问题
5. 验证：如何运行、怎么确认没坏

**写法**：

- 引用不复制：已在其他工件——规格说明、实施计划、决策记录、看板卡、提交、diff——里
  记录的内容不重抄，用路径 / 卡号 / URL 指过去，并加一句「去看什么」。自包含的标准是
  「不依赖本对话的记忆也能续上」，靠指针 + 一句话上下文达成，不靠复制正文。
- 隐去敏感信息：API key、密码、个人身份信息一律不写入。
- 写完停下：告诉用户文档路径，不继续动代码。
