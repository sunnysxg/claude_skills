# steelman — 双向钢人压力测试

反谄媚机制：不顺着用户说，也不为反对而反对——把正反两边都做成最强版，让分歧落在可检验的变量上，最后仍要给出自己的判断。流程改造自数字生命卡兹克的「双向钢人」Prompt（vault 卡 REF-双向钢人Prompt-数字生命卡兹克），第 1 步来自 Rapoport 法则（Dennett《直觉泵和其他思考工具》第 3 章）。

## 流程（顺序执行，不跳步；只在第 4 步停下来等回答）

1. **复述**：用自己的话复述用户的问题、立场和它依赖的关键前提，标明「以下按这个理解往下做」，然后直接继续。用户不打断即视为复述准确，打断了就按纠正重跑受影响的步骤。这一步防的是「让 AI 反驳我，它去找莫名其妙的点」——打的不是用户真正持有、真正依赖的东西（替对方造一个他并不持有的「最强论证」也是同一种错，等于反向稻草人）——所以复述必须显式写出来让用户能一眼核对，但不拿它当闸门卡住流程：复述错了是单点可改，先做一版靠反馈修正，比每次多一个来回便宜。
2. **双向最强**：分别给正方（用户立场）和反方的最强论证。反方只朝用户会认可的前提方向强化，不引入用户明确否定过的前提；两边都注明「这个论证最依赖哪个假设」。
3. **关键变量**：指出最可能改变结论的 1～2 个分歧点，以及什么证据或实验能分辨它们（double crux：双方各说什么证据会让自己改主意，找那个交集）。
4. **只问一题**：向用户提一个最关键的必答问题——答案直接决定结论倒向哪边——然后停下来等回答。这里不替用户假设：第 1 步的复述是 agent 能做、用户只需核对的事，所以不阻塞；这一题是只有用户能答、agent 怎么假设都是替她拍板的事，所以必须等。
5. **判断**：拿到回答后给出自己的判断与行动建议，标把握几成。不骑墙：两边论证都摆完后仍要说自己站哪边、为什么。

## 边界

- 与 grilling 的分工：grilling 把还没成形的想法问清楚（向用户提问为主）；本 skill 压力测试一个已成形的立场（产出论证为主）。第 1 步复述时发现立场、前提或目标说不清（复述不出一个可被反驳的命题），**先触发 grilling** 问到立场明确，再回到本流程从第 1 步开始——不要对着一个模糊的立场造钢人，那样正反两边都是空的。
- 用户中途纠正复述或给出新事实时，回到受影响的最早一步重跑那部分，不推倒重来。
