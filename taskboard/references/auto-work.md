# 自动工作轮：须知之外的补充

prompt 含【自动派发会话须知】（及「无仓库项目」「冻结 SSH 目标」两个变体）时读本文。这一轮的
边界——不认领、只在给定的树里干、不合并不 push、不挪 `in_review` / `done`、一次性进程、干不
下去挪 `blocked`——**以须知原文为准**，本文不复述；这里只放须知没写、这一轮又用得上的几条。

- **交付评论**照 delivery-comment.md 写（固定头两行、「用例变化」一栏、`[Sarah]` 项验收方法、
  验收入口只给常驻服务）。
- **生产卡收口后确认树干净**：须知要求把收口改动一并 commit；commit 完再跑一次
  `git status --short`，必须为空——树里残留的未跟踪文件（TODOHUB-291 是 session-log 的时间
  JSON）会让发布 saga 判脏树反复重试。无仓库项目没有这一步。
- **不改别的仓**：本卡改动波及别的仓（比如 todo_hub 改了机制、claude_skills 的 skill 文档要
  跟上），在那个项目建卡——`issue create --project <那个项目>`，验收标准写清要同步的内容，够
  自包含就直接建 `todo` 让派发器领；要等本卡上线才能做的，同一条命令带 `--blocked-by <本卡号>`
  （否则 `--related <本卡号>`），别建完再挂——派发器几秒内就会领走（见 fork-cli.md「建卡即挂
  关系」）——并在本卡交付评论用 @ 链接点名那张卡。
- **不把未提交改动留在任何仓的主检出**：落位守卫见到主检出脏就停，你留下的半成品会挡住那个仓
  所有卡的自动落位，而你在自家卡评论里写的「你说一声我就 commit」没人会看见（CLAUDESKILLS-32 /
  33 因此空转两天）。
