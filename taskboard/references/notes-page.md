# 原理留档页（只对 todo_hub 自己的卡）

**只对看板仓（todo_hub）自己的卡生效**，人手派会话和自动工作轮都一样。别的项目的卡（候选树不在
todo_hub）追加拍板节**不做留档页**，拍板节本身就是记录：页
只能随候选同笔进 `web/public/notes/`，别的仓的候选里没有这个目录，也不为它去 todo_hub 另开提交
或建卡。交付评论里不必说明「跳过留档页」。

## 什么时候做

本卡改动同笔需要往项目决策记录追加拍板节的（`docs/decisions.md` 或 `docs/decisions/`，形态见
`conventions.md` §13），做一页**原理留档页**——即那节拍板的人话展开版（行为边界、流程图、否决
理由），随候选交付，交付评论「哪里看」一节给链接。

没有拍板节的不做，她问了再补。UI 效果类永远不做（效果本身可见）；不按「机制类／流程类」之类的改动性质
自行裁量触发。

## 形式与交付

- 静态单页进看板仓 `dashi-taskboard/web/public/notes/`，文件名 snake_case 带卡号，视觉按帮助页
  token、内联主题联动脚本（样板 `todohub_92_decisions_merge.html`），随候选同笔 commit——生产卡
  交付即随部署上线。页内注明对应的决策记录节。
- 交付评论里的留档页入口只给**一条相对 Markdown 链接**（`[一句话标题](./notes/xxx.html)`）加
  一两句结论摘要：评论渲染保留相对地址，她在电脑上点它落到本机实例、在手机 web app 上点它落到
  公网（`/dev/` 开发实例已停用，TODOHUB-493；开回来时在它下面点同样留在开发实例），所以不并列「本机一条 + 手机一条」，也不写 `/` 开头的绝对
  路径或写死的域名端口（页内引用同理，闸门与理由见 todo_hub `CLAUDE.md` 的 `web/public/notes/`
  一条）。
- 留档页仍是单卡验收材料、定稿不改，内容不并入帮助页正文；但帮助页「留档页」章会按构建期扫
  `web/public/notes/` 生成的清单列出它的链接，让它多一个可发现的入口（TODOHUB-212）。
- 不用 Claude Artifact 或评论附件交验收材料（拍板见 todo_hub `docs/decisions/`）。

## 强制节

凡新建或改写机制类留档页，必须用固定二级标题**「会发生几次 · 波及谁 · 什么时候会再来一次」**
单列一节，按具体走查说明而不是只列抽象机制：至少设本仓三张卡 A、B、C，写清 A 先触发什么、B/C
在当下各自看到什么和是否要动手、A 成功/交回后 B/C 如何恢复或继续被挡；再写什么可观测的新输入会
形成下一次，而不是把本次无限重复。写完逐项自检，下面三个问题都必须能直接从这一节读到答案：

1. **会发生几次？**触发条件和去重单位是什么；本轮被处理后，什么事件才算新的一轮？
2. **我要不要动手？**每个阶段谁自动处理、谁等待；需要人工时只处理哪一个入口、为什么不用逐张处理？
3. **会波及谁？**同仓哪些卡/会话被暂停、显示或恢复；哪些卡、仓库或链路明确不受影响？
